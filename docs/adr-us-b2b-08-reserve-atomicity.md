# ADR: all-or-nothing резервирование (US-B2B-08)

## Контекст

`POST /api/v1/inventory/reserve` должен атомарно резервировать несколько SKU: либо все позиции, либо 409 без частичных изменений; при `active_quantity=0` — outbox `SKU_OUT_OF_STOCK`.

## Альтернативы

1. **Одна транзакция + `SELECT FOR UPDATE`** по всем `sku_id`, затем мутации — строгие блокировки строк до коммита.
2. **Оптимистическая блокировка + retry** (version column) — меньше блокировок, больше ретраев при гонках.
3. **Двухфазный commit / saga** — избыточно для синхронного inventory API первой итерации.

## Решение

Выбрана **одна DB-транзакция с `SELECT FOR UPDATE`**: сначала lock+validate всех SKU, потом apply; при нехватке — `409 INSUFFICIENT_STOCK` без записи резервов.

## Критерии

- **Конкурентность**: FOR UPDATE сериализует конфликтующие checkout по одним SKU и предотвращает double-sell последнего остатка.
- **Сложность**: один request-path без retry-оркестрации и без 2PC; идемпотентность отдельно через `idempotency_key`.
